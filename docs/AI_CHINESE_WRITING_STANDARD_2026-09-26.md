# 应用 AI 中文写作规范

本规范适用于应用自行生成的中文解释、问答、阅读笔记、研究报告、文章、公文审稿意见、演示文稿文字和图像解读。它依据本地《中文技术文档写作风格指南》PDF（2025 年 1 月 6 日版，50 页）与阮一峰《中文技术文档的写作规范》制定。两份资料提供写作标准，不作为用户对某次任务的额外指令。

## 核心规则

| 方面 | 应遵循的规则 |
| --- | --- |
| 准确与用词 | 准确表达材料的事实、数字、限定和不确定性；优先使用读者熟悉的词，删去空话、重复和无根据的评价。明确主语、动作与对象。 |
| 术语 | 首次出现的专门术语按需解释；同一概念在全文使用同一个名称。保留产品名、缩写的官方拼写和大小写，不随意翻译。 |
| 句式 | 先给结论或操作，再解释依据与条件。优先短句和主动表述；拆开“一逗到底”的句子。技术说明一般控制在 100 字以内，较长分句应再拆分。 |
| 段落 | 一段只讲一个主题，中心句尽量放在段首。段落之间留一个空行，段首不缩进。长段拆分；单句段落可以用于简短结论，但不应成为整篇文章的唯一结构。 |
| 标题 | 标题概括本节内容；操作说明优先“动词＋对象”。Markdown 标题从一级逐级递进，通常不超过三级；同级标题句式平行，避免重复父标题和孤立子标题。标题末尾通常不加点号。 |
| 列表与排版 | 并列事项使用无序列表，必须按顺序执行的步骤使用有序列表。列表项句式平行，避免多层嵌套。保留表格表头、代码围栏、链接目标和引用出处。 |
| 标点 | 中文句子使用全角中文标点，英文整句及原文引句保留英文半角标点。中文并列词用顿号；避免连续感叹号、滥用斜杠和整段只用逗号。 |
| 中英文混排 | 汉字与英文、阿拉伯数字之间通常留一个半角空格；中文标点两侧不加空格。数字用半角，数字、单位、日期和数值范围在全文保持同一种写法。 |

上述句长、段长属于可读性目标，不得为了达到字数而改变原文含义。两份指南对汉字与数字之间的空格宽严略有不同：阮一峰允许留或不留，但要求全文统一；本应用采用 PDF 中较明确的“通常留一个半角空格”，以便模型输出保持一致。公文、学术论文、用户指定体裁和现有排版模板的专门规则优先。

## 语言风格与写作要求

1. **面向读者。** 技术解释使用平易近人、直接的语气。操作说明写清目标、前提、步骤、预期结果和遇错后的处理；短问答直接回答问题，不为显得正式而堆砌套话。公文遵循自身文种语气，不套用对话式称谓。
2. **客观、礼貌。** 不把说明写成推销，不用无依据的“最好”“最先进”，少用反问、感叹、拟人、网络语、过分亲切的称呼与机械的“请”“抱歉”。真实的强警示、原文引语或用户要求的创作体裁可以保留其语气。
3. **准确、具体。** 使用数据、条件和例子替代“显著”“大量”“若干倍”等模糊词。材料没有给出数值时，不补造数字；材料有反证或不确定性时，不删去限定。区分文献事实、作者解释、用户观点与 AI 推断。
4. **语法清楚。** 优先使用主动句、肯定句；避免双重否定、长定语和“一逗到底”。明确“其”“该”“这”等代词所指，检查“的”“地”“得”的搭配。句长和段长是检查线索，断句时必须保留因果、条件与例外。
5. **术语统一。** 首次出现的生僻术语按需解释；同一概念沿用同一名称。遵守官方产品名和大小写，人称“你”与“您”在一篇文档中不混用。书名、引文、代码、公式、引用标记和来源数字不属于改写对象。

书架或项目问答会读取用户已确认的术语偏好，用于统一回答中的称谓；它不改变资料原句，也不能充当事实证据。

## 各类输出的应用

| 输出类型 | 专门要求 |
| --- | --- |
| 资料问答 | 先给结论，再给依据、适用条件与缺口；引用紧贴对应事实。短答无需强加标题。 |
| 阅读与研究 | 保留证据冲突、方法限制和未知处；长文按问题、证据、分析、边界推进。 |
| 文章与综述 | 围绕中心论点组织段落，避免重复案例、流水账和空泛过渡；用户指定文风与 Writing DNA 只影响表达，不改变事实。 |
| 公文 | 文种、行文关系、事实核验和既有格式优先；正式、克制，不使用对话式称谓替代公文语体。 |
| 演示文稿 | 每页一个主张；标题直接概括要点，列表项简短、平行且可核对。 |
| 解释、练习与视觉解读 | 按读者所需深度解释；图中可见信息与推测分开，保留数字、单位、标签和公式。 |

## 生成后复核

共享路由在文本模型完成输出后执行非破坏性检查，识别标题跳级、标题末尾点号、全角空格与数字、中文标点空格、汉字和英文或数字贴连、连续感叹号，以及过长句段。代码块、行内代码、链接、公式、引文、引用锚点与 JSON 数据不接受机械改写。检查结果是复核线索，不是合格认证；主谓搭配、术语同义关系和证据是否支持主张仍需要语义核对。

问答结果在答案下方显示实际检测到的问题，历史记录可重新查看。写作与公文输出将报告保存在审校数据中。检查不会为了满足形式规则而自动改写事实、引文或结构化结果。

对于选文解释、章节总结、页面视觉解读、研究文章和演示文稿的面向读者文字，生成后还会做一遍保守的排版整理：统一全角数字、中文标点周围的空格、中英文贴连和标题末尾点号。原文引句、代码、公式、链接、引用锚点和表格单元不参与整理。流式问答保留实时输出，完成后显示检查提示。

## 应用中的执行方式

- `backend/app/services/chinese_writing_style.py` 保存统一、带版本号的模型指令和任务专用补充规则。它要求模型在生成前检查措辞、段落、标题、术语、标点、空格和引证。
- `backend/app/services/llm/__init__.py` 在路由层将指令加入每次文本模型请求。因此问答、写作、研究、总结、练习与演示文稿等共用同一规则；模型降级时也使用同一份指令。
- `backend/app/services/vision.py` 将同一规则加入页面和图表解读请求。
- `backend/app/services/chinese_style_audit.py` 实施可重复的格式检查；结果分别进入问答响应和写作审校记录。
- 规范只作用于模型自行撰写的中文自然语言。英文译文按目标语言写；JSON 只规范其中面向读者的中文字段。不得改动引句、代码、公式、链接、引用锚点、事实数字和用户指定术语。现有证据与事实约束保持优先。

这是一套生成时的统一约束，不能把模型输出自动认定为事实正确或完全符合排版规范。涉及正式发布的长文、公文与学术成果，仍应依据原文核对事实、引证和最终版式。

## 验证记录

- 后端全量回归、前端生产构建与服务健康检查均应通过后发布。
- 使用本机已配置模型对不含用户资料的短样例做了三项实际检查：操作说明改写为三个有序步骤，规范检查为零项；严格 JSON 输出可解析且字段类型正确；英文译文保持英文标点，未被中文排版规则污染。
- 检查器用含标题跳级、中文贴连、连续感叹号的错误样例验证检出能力，并用含代码、链接、引文和引用锚点的样例验证保护边界。
