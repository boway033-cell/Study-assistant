# 项目理解档案：迭代 C 已实现

日期：2026-09-27

## 使用路径

进入“我的助手 → 项目档案”，选定书架或项目的范围快照和一条已确认的研究判断。在“区分性阅读与研究设计陪练”中填写 A、B 两种解释，各自的前提和不同的可观察预测；可补充用户关注的群体、时期或机制。保存后先看所选书目、研究模型和估计用量，再启动生成。默认最多给三条阅读任务。

有原页的任务附短引、页码和“打开原页”；服务端检查文献属于快照、正文版本未变、短引确实在文本块中。没有可用原页时，任务明确标为“需找外部资料”，说明所需数据类型。AI 没有权限把任务自动标成用户结论。

用户复核后可选择“支持 A / 支持 B / 两者都不支持 / 仍不清楚”。结果和备注会追加到判断的修订历史；原页证据作为触发修订的线索保存，但其证据关系保留“尚不明确”，避免把阅读任务误当成已经证明判断的材料。外部资料任务若作方向性判断，须由用户填写可追溯的来源线索；系统明确标明该线索尚未经核验。任务来源变化后不可继续提交原页复核。

陪练选择当前快照中的文献，要求该书已有完成且版本有效的全文研读资产。系统沿用资产的材料类型，在相关论证节点与原页上每轮只提出一个问题：定量研究聚焦测量、对照和识别假设；质性研究聚焦案例、负例和解释过程；理论文本聚焦前提和推演；综述聚焦搜集与纳排范围。用户先回答，再查看反馈。反馈显示可逐字核对的“原文如此说”，另列“AI 对原文的解读（待核对）”“你的推断”“AI 下一步建议”和仍存疑处。回答和反馈分别保留在修订记录中。

重新打开档案时优先定位有来源变化或未解决阅读任务的判断；任务列表也按来源变化、未解决和区分性因素排序。

## 接口

接口统一位于 `/api/assistant/research`，每次按 `scope_type/scope_id` 校验范围归属。

| 方法与路径 | 作用 |
| --- | --- |
| `PUT /items/{id}/rivals` | 保存两种解释、前提、预测和用户兴趣；追加修订。 |
| `POST /reading-tasks/preview`、`POST /reading-tasks/generate` | 先预览书目、模型和用量，再经 `acknowledged=true` 提交后台任务。 |
| `GET /items/{id}/reading-tasks`、`POST /reading-tasks/{id}/outcome` | 按优先级读取任务，记录用户复核并修订判断。 |
| `POST /coach/preview`、`POST /coach/question` | 预览材料类型、原页和用量，后台生成单个问题。 |
| `GET /items/{id}/coach-turns`、`GET /coach/{id}/feedback-preview`、`POST /coach/{id}/answer` | 读取陪练、预览反馈用量、保存用户回答并后台生成分层反馈。 |

后台任务名：`research_reading_plan`、`research_coach_question`、`research_coach_feedback`。模型输出经结构化及原页校验后保存；重试和失败不会覆盖已确认的判断。任务与陪练使用既有 `research_items / research_evidence / research_revisions`，无需新表或数据库迁移。

## 验证

`backend/tests/test_research_design.py` 覆盖不同预测、虚构页码与短引拦截、外部资料线索、复核修订、来源失效、四种材料类型、跨范围拒绝、后台去重和陪练回答/反馈分离。前端经 `npm run build` 验证。
