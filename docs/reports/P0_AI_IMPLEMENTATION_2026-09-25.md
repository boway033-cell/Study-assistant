## 参照成熟产品的下一步建议

1. **证据矩阵与逐格回原文。** [Elicit](https://elicit.com/solutions/systematic-review) 把抽取字段、依据片段和人工复核放在同一工作区。下一阶段先做“文献 × 研究问题/方法/样本/结论/局限”矩阵，每格保存原页锚点、AI 初判、人工确认状态。先支持单个研究项目，不扩展成完整系统综述。验收：任意结论一键回到支撑片段；无片段的格子不能显示为“已证实”。
2. **从笔记直接回页。** [Zotero](https://www.zotero.org/support/pdf_reader) 将标注、笔记、引文和原页连起来。现有来源锚点可作为基础；下一步对失效锚点提供逐对象修复，并在研究报告审阅时并排显示主张与原页。验收：研究者核对一条主张无需在多个工作区手工搜索。
3. **把模型输出质量拆开评测。** [Elicit 公布的评测方法](https://elicit.com/blog/evaluating-elicit-slr) 分别检查检索、筛选与抽取。本产品应按“召回 → 证据抽取 → 主张支持 → 冲突保真 → 成文”建立脱敏固定样本，记录提示词版本与模型。优先收集扫描件、表格、相互矛盾的研究和无答案问题。验收：每次提示词或模型调整都能看到各层改善及退化，且有人工抽检。
4. **证据缺口的第二轮判断。** 本轮已为规划需求补候选检索；下一步在成文前让系统逐项检查候选片段是否真的满足需求。不满足时只在已选书目内再检索一次，仍不足则收缩主张并向用户说明缺什么。验收：报告不会把“找到了一个含关键词的片段”写成证据充分。

## 仍需实测的边界

本轮没有调用真实模型，因此只能证明控制流和提示词变化，不能声称答案更准确或研究结论更深入。引用编号检查已修复，但语义支持性仍是 `not_checked`。PPTX 视觉质量与真实大库扫描资料也未在本轮验证。
