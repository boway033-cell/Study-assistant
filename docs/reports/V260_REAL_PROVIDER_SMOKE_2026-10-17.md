## 3. 报告

### 估算与预算

- 报告估算：2 次调用、20,902 估算 token。
- 本次设置上限：40,000 token / 3 次调用（约估算的 1.2 倍）。
- 实际第一次任务：综合成文成功，正文 **1,984 字** 已保存；审计开始时触发“本次 AI 任务已达到 40000 估算 Token 上限”，审计状态为 failed。
- 单独重跑审计：估算 9,362 token，设置 60,000 token / 3 次调用；审计完成。

这说明两件事：

1. v2.6 的“**正文先入库、审计失败可单独重跑**”路径在真实模型上确实生效，正文没有丢；
2. 该书的报告估算偏低：估算 20.9k，实际综合调用后余量不足以覆盖审计，4 万上限偏紧。建议把“生成 + 首次审计”的估算合并得更保守，或在界面提示用户为审计预留额度。

审计明确指出的问题包括：

- 从“伯林承认两种自由同源”推到“伯林的区分没有分析价值”，中间依赖麦卡勒姆公式，但公式与伯林问题是否同一层次未论证；
- “伯林几乎故意划分两种自由”是动机推断，缺少伯林自述或书信证据；
- 报告称伯林混淆自由与自由权利、并拒绝把贫困无助归入不自由，但所给片段未出现该句，claim 8 因此为 needs_review；
- 退出契约的论证依赖博弈与自然法前提，原文只有一句带过；
- 把伯林问题转换为消极权利/积极权利问题，需要说明权利与自由的关系及转换是否保留伯林的核心关切。

这些结果是真实模型输出经过真实审计后的结果，**不是“全绿”**；它恰好说明审计没有对流畅正文放行。

## 6. 建议

1. **把报告预算下限提高**：该书 1,200 字目标实际需要约 4 万 token 才能覆盖“综合 + 审计”；建议估算时把审计额度单独列出，或在 40k 上限时提示“审计可能无法完成”。
2. **不要用词面筛查代替语义核验**：本次问答引用编号全部有效，但词面筛查只有 5.88%；界面应继续显示“需人工复核”，不能显示“引用已核验”。
3. **把“正文超目标长度”显式暴露**：目标 1,200 字、实际 1,984 字；如果产品承诺目标字数，应在报告页显示实际字数与超出比例。
4. 若要在 CI 中固化真实 provider 冒烟，建议固定使用书 107、目标 1,200 字、预算至少 60k token，并只跑一次/天。
