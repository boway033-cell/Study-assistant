# 04 · 开发路线图

- 版本：v0.2（已按「低内存占用 / FTS5 检索优先 / 向量检索 P1 可选」修正）
- 预估：单人 4~6 周（每天 2~4 小时投入）
- 配套：全部 docs 文档

## 0. 总原则

- **每阶段结束都有可演示的成果**，先纵向打通、再横向铺开
- 先做「导入 → 解析 → 搜索 → 问答」的最小闭环，再叠加记忆与刷题
- 遇到难啃的（OCR、复杂表格、向量检索）先降级为可选项，不阻塞主线
- **低内存优先**：P0 检索只用 FTS5（零模型内存）；嵌入模型与本地 LLM 均按需启用
- 每阶段末尾提交一次 git commit / tag
- 开发环境：Python 3.14（已实测核心依赖可安装）；所有操作仅在 `study-assistant/` 目录内，不触碰系统原有文件

## 阶段 1：AI 对书提问（第 2 周）

**目标**：对着书提问，流式回答，答案带出处。

### 任务清单

| # | 任务 | 说明 | 验收 |
|---|---|---|---|
| 1.1 | 文本切片器 | 按章节 + 固定窗口（600 字/80 重叠）切 chunks | 无跨章断裂 |
| 1.2 | **FTS5 关键词检索器（P0 主检索）** | 问题 jieba 分词 → FTS5 MATCH top-k → prompt 组装 | 命中相关章节 |
| 1.3 | LLM 抽象层 | base/ollama/deepseek/router（见架构 §5） | 双 provider 可切换 |
| 1.4 | RAG 问答 API | 检索片段 → LLM 流式生成（SSE）+ sources 返回 | 打字机效果，答案带页码 |
| 1.5 | 问答页 UI | 对话界面、流式渲染、出处页码可点击跳转 pdf.js | 全流程体验 |
| 1.6 | 设置页 | LLM 模式切换 + API Key + 连接探测 | 一键切换生效 |
| 1.7 | 对话历史 | chat_logs 存取、删除 | 历史可回看 |
| 1.8 | 【P1 可选】向量检索 | fastembed + ChromaDB；设置开关 `vector_search` 默认关闭 | 开启后质量提升，关闭零开销 |

**里程碑**：✅ 5 道专业问题（如"解释特征值的几何意义"）回答准确、可追溯页码。

> **检索策略**：P0 只用 FTS5 关键词检索（BM25 风格，零内存、无模型下载）即可支撑 RAG 问答；向量检索（fastembed）为 P1 可选增强，按设置开关按需启用，避免常驻模型占用内存。

## 风险清单（含缓解）

| 风险 | 影响 | 缓解 | 触发预案 |
|---|---|---|---|
| 教材无目录/目录乱 | 章节树不准 | 启发式分级 + 手动编辑章节 | 阶段 0.6 预留编辑接口 |
| 扫描版 PDF | 无法检索/向量化 | 检测文本量提示 OCR | OCR 排 P1，不阻塞主线 |
| 本地 LLM 效果差 | 问答质量低 | 双模式，默认推荐云端 | 阶段 1 先接 DeepSeek 验证效果 |
| 向量化慢 | 导入体验差 | 后台任务 + 进度条 | 模型换 bge-small-zh 量化版 |
| 生成卡片质量差 | 复习体验崩 | 预览确认机制 | 生成 prompt 迭代优化 |
| 单机性能瓶颈 | 大书卡顿 | 分页读取、chunk 上限 | 按需索引优化 |
