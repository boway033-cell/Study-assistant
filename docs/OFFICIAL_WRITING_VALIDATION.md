# 公文写作接入验证

日期：2026-09-07。随 v2.2.0 发布；保留 v2.1.0 历史标签。

## 已实现

- 写作工作台的“研究写作 / 公文写作”切换；原功能保留，沿用当前配色。
- 公文直达地址 `/writing/official` 自动转入 `/writing?mode=official`；刷新保留模式，切换按钮支持浏览器前进/后退，侧栏标明两类写作。
- 19 个文种，主体/主送/行文关系/事实材料/目标字数输入。
- 模型传输需显式同意；仅发送本稿输入，不自动搜集文献。
- 生成提纲 → 编辑并确认 → 展开正文，后端拒绝未确认提纲的正文生成。
- 正文自动检查、模型审稿、按指定意见改稿、历史回读和不可覆盖的正文版本。
- 文种/缺失项/待核数字检查；真实 lieflat 检查器提供已有基线的统计参考。
- 真实 official-document 原始规则用于起草、审稿及修订，不只是展示技能名称。
- 真实 sanmu 引擎负责 DOCX、元数据清理及结构验证，未另写一套 OOXML 排版。
- 本篇格式设置与经差异确认的默认设置分离；默认配置不存正文或单位。
- 保存与确认有内容指纹；旧写作接口不能覆盖公文版本。
- 150 秒模型超时与 60000 字符输出上限；模型异常不泄露配置、密钥或供应商原始错误。

## 验证结果

- 后端全量：173 passed、1 skipped，其中公文专项 15 项。
- 前端单元：37 passed，其中排版差异专项 2 项。
- Vite production build：通过。
- 浏览器虚构资料流程：开发服务及最终生产构建均通过；覆盖公文直达、刷新、前进后退、材料授权、确认门槛、编辑失效、起草、审稿、改稿、导出、格式差异与取消、恢复预设、模式切换保留稿件。
- 宽度检查：1920、1440、1280、1024、900、768、390、320 px，操作按钮未裁切，检查容器无横向溢出，页面脚本错误为 0。
- DOCX：实际引擎结构验证通过，正文事实保留、A4 宽度与个人元数据清理通过测试。
- 页面检查：打包 `render_docx.py` 因 Windows 运行时未提供 LibreOffice 失败；未调用用户安装的 LibreOffice。改用项目已有只读 Word 渲染脚本（隐藏、禁用宏、虚构测试稿）生成 1 页 PDF，并用 bundled pypdfium2 转为 PNG 检查。标题、正文、落款及页码可读，无裁切、重叠或缺字。
- 本机缺少预设小标宋，保留引擎的缺字库/替代警告，不安装字体、不冒充精确字体匹配。

测试脚本：`backend/tests/test_official_writing.py`、`frontend/tests/officialFormat.test.js`、`scripts/official_writing_ui_smoke.cjs`。
浏览器脚本需 Playwright（可用 bundled runtime 的 NODE_PATH），只访问本机前端，所有 `/api/` 请求被替身拦截。

## 明确边界

- 未调用真实付费模型，不能将模拟响应测试宣称为真实模型写作质量验收。
- 单份合成测试稿的页面检查不能保证任意长文分页；运行时导出始终注明“结构通过、页面视觉未核验”。
- 没有自动确认事实真实性、政策合法性或签发权限；占位符须人工补齐。
- 本次不实现库内知识对象选择器、已有 DOCX 上传重排、表格转换、后台取消任务或并发协作编辑。
- lieflat 使用其真实诊断脚本和提纲确认流程，不包含全部范文/DNA 语料；法定文种无统计基线时明确显示不适用。
- 三方原始许可证及来源已保留；融合功能含非商业许可材料，参见 `THIRD_PARTY_NOTICES.md`。
