# 研究型工作区 UI 契约

本契约将本轮检索到的 UI/UX 方法转成项目自己的约束。它不引入新的运行时依赖。

## 产品气质

- 方向：克制的编辑型研究台，而不是营销仪表盘。
- 视觉：暖纸色、深青、暖赭；色彩表达状态和层级，不用于制造无意义装饰。
- 密度：资料管理可紧凑，长文阅读必须留白；同一页面不同时追求“数据密集”和“文章沉浸”。
- 动效：120–180ms 的颜色、边框、展开反馈；尊重 `prefers-reduced-motion`，不依赖位移说明状态。

## 信息架构

- 一级导航只承载稳定职责：知识库管理、阅读与研究、创作与输出。
- 关键能力不得只存在于抽屉或另一功能内部；写作台、健康检查必须有独立路由。
- 抽屉用于短暂检查、编辑和对照，不作为长期核心工作区。
- 当前导航项必须有清晰选中态；图标必须同时有文字，不靠用户猜测。

## 长文阅读

- 笔记、研究报告等长文默认提供全屏或沉浸模式。
- 主体行宽约 65–76 个中英文字符；推荐 `width: min(100%, 76ch)`。
- 正文字号桌面端约 17px，行高 1.85–1.95；移动端可降至 16px，但不得横向裁切。
- 来源、主张审计和元数据放在辅助栏；窄屏移到正文之后，不能持续压缩正文。
- Markdown 标题、段落、列表、引文应保持稳定节奏，正文不能被卡片逐段切碎。

## 交互与可访问性

- 操作使用语义化 `button`/`a`，纯图标按钮提供可访问名称。
- 键盘焦点清晰可见；弹窗/抽屉关闭后焦点返回触发点。
- 点击目标至少 44×44 CSS px；移动端不依赖 hover。
- 加载区使用 `aria-live` 或等效反馈；错误信息说明发生了什么以及下一步。
- 横向滚动只允许在明确的筛选条、表格或画布中；正文和页面根节点不得溢出。

## 状态完整性

每个远程或后台功能都应覆盖：初始空状态、加载、进度、取消/中止、成功、失败、重试、部分完成。AI 输出还要显示来源范围、置信/审计状态以及是否已经写入知识库。

## 实现审查清单

- 入口能否在 1–2 次选择内到达？
- 用户是否始终知道当前书目/知识对象范围？
- 长文能否不受侧栏挤压阅读？
- 修复按钮是否真的到达可执行位置，而不是泛化首页？
- 结果能否返回具体原页、章节或文本块？
- 390px、800px、1065px、1600px 是否无根级横向溢出？
- 前端契约测试、生产构建、关键路由真实截图是否通过？
